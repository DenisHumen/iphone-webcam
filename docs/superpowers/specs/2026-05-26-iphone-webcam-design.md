## 1. Резюме

ClearCam превращает iPhone в высококачественную (вплоть до истинно несжатой) веб-камеру для
компьютера. iPhone снимает и передаёт видео на десктоп по **Wi-Fi или USB** под единым протоколом;
десктоп показывает живое превью, даёт управление и публикует поток как **системную виртуальную
камеру** (Zoom/Meet/OBS/запись). Качество **гибридное**: истинный raw, когда канал тянет, иначе —
visually-lossless; выбор делает встроенный **тест скорости** и адаптация на лету.

## 2. Проблема, цели, не-цели

Истинно несжатое видео по Wi-Fi физически ограничено пропускной способностью; пользователю нужна
честная система, которая выжимает максимум качества из доступного канала и не «зависает» на
недостижимых режимах.

- **Цели:** см. [01-vision-and-requirements.md](../../01-vision-and-requirements.md) §2 (G1–G9).
- **Не-цели v1:** звук, несколько телефонов, запись на телефоне, интернет/NAT, Android, эффекты,
  Windows 10 как первичная цель. См. §3 там же.

## 3. Зафиксированные решения (ключевое)

| # | Решение | ADR |
|---|---|---|
| Назначение | Виртуальная камера **+** просмотр/управление | ADR-001 |
| Качество | Гибрид: raw ↔ visually-lossless, по тесту скорости | ADR-002 |
| Камеры | Объективы одного iPhone сейчас; абстракция `Source` на будущее | ADR-003 |
| Транспорт | Wi-Fi + USB под одним протоколом (CCP); кабель приоритетнее | ADR-004 |
| Звук | Вне v1; протокол резервирует аудио-дорожку | ADR-005 |
| Платформы | macOS → Windows → Linux | ADR-006 |
| Десктоп-стек | Rust-ядро + Tauri (TS/React) UI + нативные sink'и | ADR-007 |
| iPhone-стек | Swift / SwiftUI / AVFoundation / VideoToolbox | ADR-008 |
| Соединения | Два TCP: control (JSON) + media (binary) | ADR-009 |
| Формат кадра | NV12 (YUV 4:2:0) | ADR-012 |
| Виртуальная камера | CMIO (mac) · MFCreateVirtualCamera (Win) · v4l2loopback (Linux) | ADR-013/014/015 |

Полный список с обоснованиями и отложенными решениями — [12-decisions-log.md](../../12-decisions-log.md).

## 4. Архитектура (обзор)

```
iPhone (Swift)                              Десктоп (Rust core + Tauri)
 Capture(AVF) ─► Encoder(raw/VT) ─► Transport ══ control(JSON) ══ Transport ─► ControlPlane ◄─► AdaptiveEngine
 StatusAgent ───────────────────────────────╝   media(binary)  ╚──────────► MediaPipeline ─┬─► VirtualCameraSink
 SwiftUI (preview/status)                                                                    ├─► PreviewProvider ─► Tauri UI
                                                                                            └─► Recorder (опц.)
        └────────── Wi-Fi (TCP,mDNS,QR) │ один протокол │ USB (usbmuxd) ──────────┘
```

- Два логических плана (control/media) по двум TCP-соединениям.
- Платформенное — только за трейтами (`Transport`, `FrameSink`, `Decoder`); ядро портируемо и
  тестируемо с моками.
- Канонический формат конвейера — NV12. Backpressure — drop-oldest (задержка важнее полноты).
- Абстракция `Source` — задел под несколько телефонов.

Детали, диаграммы, модель конкурентности и домены отказов — [02-architecture.md](../../02-architecture.md).

## 5. Протокол (CCP v1)

- Два TCP-соединения: **control** (length-prefixed JSON) и **media** (28-байтный бинарный заголовок +
  payload: raw NV12 либо length-prefixed NAL для HEVC/H.264).
- Направление dial скрыто адаптером (Wi-Fi: десктоп слушает; USB: телефон слушает) — ADR-010.
- Обнаружение mDNS `_clearcam._tcp`; привязка по QR-токену; ручной ввод; handshake + auth; версии/caps.
- Тест скорости — нагрузка по media (ramp), измерение goodput/RTT/джиттера.
- Расширяемость: тип media `2`=audio (резерв), несколько `Source` без слома совместимости.

Полный каталог сообщений, форматы и сценарии — [03-protocol.md](../../03-protocol.md).

## 6. iPhone-приложение

Захват NV12 (AVFoundation), переключение объективов (`DiscoverySession` + reconfigure), кодирование
(raw-passthrough или VideoToolbox low-latency), транспорт (Network.framework для Wi-Fi, `NWListener`
для USB), телеметрия (батарея/тепло/метрики), state machine сессии, экраны Connect/Streaming/Settings.
Детали — [04-ios-app.md](../../04-ios-app.md).

## 7. Десктоп-приложение

Rust-крейты: `ccp-protocol`, `transport`(wifi/usb), `session`(ControlPlane-actor), `adaptive`,
`mediapipeline`, `decode`, `sink`, `app`. Tauri-обвязка (commands/events) + UI (React/Vite/Tailwind,
`<canvas>`-превью, график метрик). Стоки виртуальной камеры — платформенные за `FrameSink`.
Детали — [05-desktop-app.md](../../05-desktop-app.md).

## 8. Адаптивный движок и тест скорости

Измеряет устойчивый goodput видео-пути (ramp по media + PING/PONG), выбирает максимальный режим в
пределах caps и транспорта с запасом (headroom 0.70), при равных res/fps предпочитает raw; на лету
адаптируется (гистерезис/cooldown), реагирует на тепло/заряд. Таблицы битрейтов и псевдокод —
[06-adaptive-engine-and-speedtest.md](../../06-adaptive-engine-and-speedtest.md).

## 9. UI/UX

Минимализм, тёмная тема, семафор качества канала, подключение ≤3 действий, честная индикация
достижимых режимов, симметричное управление объективом (ПК и телефон). Экраны и состояния (с
ASCII-макетами) — [07-ui-ux.md](../../07-ui-ux.md).

## 11. План реализации (фазы)

0 Фундамент → 1 Транспорт/handshake → 2 RAW-видео+превью → 3 Виртуальная камера (macOS) →
4 Кодер/гибрид/тест скорости/адаптация → 5 USB → 6 Полировка до v1. После v1: 7 Windows, 8 Linux,
9 Звук, 10 Мульти-источник. Каждая фаза — вертикальный срез с критериями приёмки; перед кодом —
навык `writing-plans`, затем TDD. Детали — [10-roadmap-and-plan.md](../../10-roadmap-and-plan.md).

## 12. Тестирование

Unit (протокол/адаптация/конвейер/state machine), integration (мок-iPhone по loopback), эмуляция
канала, платформенные ручные чек-листы (DoD macOS), перцептивная проверка visually-lossless,
soak/производительность. Детали — [11-testing-strategy.md](../../11-testing-strategy.md).

## 13. Риски

- CMIO-расширение + подпись/нотаризация (macOS) — главный риск, вынесен в Фазу 3, есть референсы.
- USB/usbmuxd кросс-платформенно — Фаза 5, ADR-019.
- Истинный raw по Wi-Fi нестабилен — управляется тестом скорости/адаптацией (by design).
- Сквозная задержка — контролируется drop-oldest и low-latency кодеком, измеряется с Фазы 2.
