# 10 — Дорожная карта и план реализации

Связано: [01-vision-and-requirements.md](01-vision-and-requirements.md) (DoD),
[08-project-structure.md](08-project-structure.md), [11-testing-strategy.md](11-testing-strategy.md).

## Принципы исполнения

- **Вертикальные срезы.** Каждая фаза заканчивается чем-то наблюдаемым, а не «слоем в стол».
- **macOS-first.** Сначала образцовый v1 на macOS; Windows/Linux — отдельные фазы после v1.
- **Перед кодом фазы — план.** Использовать навык `superpowers:writing-plans` для детального плана
  конкретной фазы, затем `superpowers:test-driven-development` (тесты вперёд).
- **Мок раньше железа.** Мок-iPhone на Rust (`tools/`) позволяет разрабатывать и тестировать ядро без
  телефона; реальный iOS-клиент подключается на соответствующих фазах.
- **Каждая фаза — свои критерии приёмки.** Не переходить дальше, пока они не выполнены и проверены
  (навык `superpowers:verification-before-completion`).

---

## Фаза 0 — Фундамент

**Цель:** скелет репозитория и общий контракт протокола.

- Rust workspace (`desktop/`), пустые крейты по [08](08-project-structure.md).
- Крейт **`ccp-protocol`**: типы control (serde) + кодек/декодек бинарного media-заголовка + версии/caps.
- Скелет iOS-проекта (`ios/`) + модуль `Protocol/` (зеркало форматов).
- CI: `fmt`/`clippy`/`test` (Rust); линт UI; (на macOS-раннере) сборка iOS-скелета.
- Каркас Tauri-приложения (`cargo tauri dev` открывает пустое окно).

**Приёмка:** всё собирается; round-trip тесты `ccp-protocol` (control JSON и media-заголовок) зелёные;
CI проходит. **Кода фич ещё нет.**

## Фаза 1 — Транспорт и handshake (Wi-Fi, loopback)

**Цель:** установление сессии и обмен control без видео.

- `transport` (трейт + `wifi` TCP), два соединения (control/media), framing.
- `session` (ControlPlane) — handshake, auth по токену, `DEVICE_INFO`, `CAMERA_LIST`, `TELEMETRY`,
  `PING/PONG`.
- `tools/mock-iphone` — Rust-клиент, проходящий handshake и шлющий телеметрию.
- Десктоп-UI: экран подключения, QR-генерация, список устройств (mDNS), статусы.
- iOS: `TransportClient` (Wi-Fi), `SessionController` (handshake), отправка `DEVICE_INFO`/`TELEMETRY`.

**Приёмка:** реальный iPhone (и/или мок) подключается по Wi-Fi (скан QR), проходит handshake; десктоп
показывает имя устройства, заряд, список камер, живую телеметрию. Разрыв → переподключение.

## Фаза 2 — Видео-путь RAW (Wi-Fi) + превью

**Цель:** живое изображение на десктопе (без виртуальной камеры).

- iOS `CaptureEngine` (NV12), `Encoder` raw-путь, отправка media-кадров (формат [03](03-protocol.md) §5.2).
- Десктоп `mediapipeline`: приём raw, джиттер-буфер с drop-oldest, нормализация NV12.
- `PreviewProvider` → Tauri UI (`<canvas>`), throttle.
- Переключение объективов (`SET_CAMERA`) с UI → отражается в превью.

**Приёмка:** живое RAW-превью ~720p30 по Wi-Fi в десктоп-UI; переключение объективов < 1 c;
задержки/дропы в пределах NFR; нет роста буфера.

## Фаза 3 — Виртуальная камера (macOS CMIO)

**Цель:** поток виден другим приложениям как системная камера.

- `sinks/macos-extension`: CMIO Camera Extension (Swift) + контейнер-glue; передача кадров
  ядро→контейнер→расширение (XPC/IOSurface).
- Трейт `FrameSink` + macOS-реализация; `mediapipeline` подаёт кадры в sink.
- Скрипты установки/удаления расширения; обработка отсутствия разрешения.

**Приёмка (DoD-2):** «ClearCam» появляется в Zoom, Google Meet (браузер), OBS, QuickTime и показывает
живой поток с iPhone (пока RAW/Wi-Fi). При разрыве — «Нет сигнала», камера не пропадает.

## Фаза 4 — Кодер, гибрид, тест скорости, адаптация

**Цель:** автоматический выбор качества и работа на обычном Wi-Fi.

- iOS `Encoder` encoded-путь (VideoToolbox HEVC/H.264, low-latency); `config`-кадры/параметры.
- Десктоп `decode` (VideoToolbox) → NV12; единый путь в `mediapipeline`.
- `adaptive`: `SpeedTest` (ramp по media), выбор режима, цикл адаптации (см. [06](06-adaptive-engine-and-speedtest.md)).
- UI: оверлей теста скорости, режим Авто/RAW/Lossy, баннеры адаптации, график битрейта.

**Приёмка (DoD-5/6 частично):** тест скорости рекомендует режим; на обычном Wi-Fi авто visually-lossless
1080p без обрывов; деградация/восстановление работают; метрики корректны.

## Фаза 5 — USB-транспорт

**Цель:** кабель как приоритетный высококачественный канал.

- `transport/usb` (usbmuxd): enumerate, connect к портам устройства; iOS `NWListener` (server по USB).
- Авто-определение кабеля; выбор более быстрого канала; USB-привязка (доверие устройству).

**Приёмка (DoD-6):** при подключении кабеля приложение переключается на USB; на iPhone 15 Pro+ доступен
истинно несжатый 1080p60; задержка по USB ≤ ~80 мс.

## Фаза 6 — Полировка до v1 (macOS)

**Цель:** довести до Definition of Done.

- UX-полировка экранов, состояний, ошибок; тепловые/батарейные предупреждения.
- Запись (опц., может стать v1.1).
- Стабильность переподключений; нагрузочные и длительные прогоны; диагностический режим.
- Документация пользователя (установка расширения, разрешения).

**Приёмка:** все DoD-1..8 из [01](01-vision-and-requirements.md) §7 выполнены и проверены по
[11-testing-strategy.md](11-testing-strategy.md).

## После v1

- **Фаза 7 — Windows:** sink на `MFCreateVirtualCamera`; USB через Apple Mobile Device Support; адаптация
  UI/упаковки. Декод — VideoToolbox недоступен → ffmpeg/MF decoder.
- **Фаза 8 — Linux:** sink на v4l2loopback; пакетирование; декод через ffmpeg/VAAPI.
- **Фаза 9 — Звук:** аудио-дорожка в протоколе (тип media `2`), виртуальный микрофон на ПК, AV-синхрон.
- **Фаза 10 — Несколько источников:** коллекция `Source`, активный источник/переключатель в UI.

## Главные риски (и где смягчаем)

- **CMIO-расширение и подпись/нотаризация** — самый рискованный кусок macOS; вынесен в отдельную Фазу 3,
  есть референсы (Celluloid, daily-virtual-camera, ldenoue/cameraextension). См. [12](12-decisions-log.md).
- **USB/usbmuxd кросс-платформенно** — нюансы по ОС; Фаза 5, ADR по выбору библиотеки.
- **Истинный raw по Wi-Fi нестабилен** — управляется тестом скорости/адаптацией (Фаза 4) — by design.
- **Задержка end-to-end** — контролируется drop-oldest и low-latency кодеком; меряется с Фазы 2.
